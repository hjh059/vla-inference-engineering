# 机器学习与线性代数基础

本文说明理解本项目推理部署、模型计算和 BF16 GEMM 优化所需的共同基础：模型如何训练、参数和推理的关系，以及张量和矩阵计算。它不记录当前实验配置或性能结论；这些内容以[项目范围](../README.md#vla-推理部署与优化)和[实验记录](../experiments/README.md#实验流程)为准。

## 模型学习、训练与推理

### 模型学习的基本逻辑

从高层抽象看，数据驱动模型都在训练数据、模型结构、训练目标和优化算法共同约束下调整参数，使损失函数 `L` 尽可能小：

```text
训练数据 + 模型结构 + 训练目标 + 优化算法
                    ↓
              不断调整模型参数
                    ↓
          让输出尽量符合训练目标
```

训练数据决定模型见过哪些案例，模型结构决定信息如何处理，训练目标定义哪些输出得到更高评价，优化算法决定如何降低损失。模型学习的是由数据、奖励或约束所定义的统计映射，而不是直接获得现实世界中的绝对真理。

不同类型模型的输入与目标不同：

| 模型 | 输入 | 主要学习目标 |
|---|---|---|
| LLM | 上下文 token | 预测下一个 token 的概率分布 |
| VLA | 图像、语言指令、机器人状态 | 预测专家动作或动作分布 |
| 图像分类模型 | 图像 | 预测人工标注的类别 |
| 扩散图像模型 | 文本、带噪图像 | 学习从噪声生成或恢复图像 |
| 世界模型 | 当前状态和动作 | 预测未来状态 |
| 强化学习策略 | 环境状态 | 最大化长期累计奖励 |

LLM 常学习 `p(下一个 token | 前面的 token)`；VLA 可概括为 `p(动作 | 图像、指令、机器人状态)`。输出能否接近现实中的正确结果，还取决于数据质量和覆盖、输入标签对应、目标设计、模型和优化是否合适、推理环境是否接近训练分布，以及是否具备闭环反馈、安全约束等条件。

### 模型训练、参数与推理

训练的基本循环是：提供输入，模型预测，计算预测与目标的损失，通过反向传播得到参数梯度，再由优化器更新参数并在大量数据上重复。

```text
输入数据 → 前向传播 → 模型预测 → 计算损失
                                  ↓
                    优化器更新参数 ← 反向传播
```

神经网络的基本计算可写作 `输出 = 输入 × 权重 + 偏置`。参数是训练后大量数值系数，通常共同、分布式地表示转换规律；activation 则是本次输入产生的临时中间状态。连续值回归可使用均方误差 `L = (预测值 - 目标值)²`，LLM 常用交叉熵，VLA 则可能使用动作回归、token 交叉熵、扩散去噪或 flow-matching 目标。

反向传播回答“每个参数应向哪个方向调整才能让损失降低”。普通推理使用训练完成后固定的参数：

```text
训练阶段：不断调整参数
推理阶段：使用固定参数处理新输入
```

## 张量表示与维度操作

张量（tensor）是带有形状（shape）的多维数值数组；标量、向量、矩阵分别是 0、1、2 维张量：

```text
标量：一个数；形状 []；                 例：3.14
向量：一排数；形状 [3]；                例：[1.2, 2.3, 3.4]
矩阵：多行多列的数；形状 [2, 3]；       例：[[1, 2, 3],
                                             [4, 5, 6]]
```

张量的轴数也称秩（rank）。向量 `v[i]` 和矩阵 `M[i, j]` 都通过索引定位元素。工程中，向量可看作按固定顺序排列的数值；更严格地说，它是可进行加法和数乘的量。几何中的箭头、物理的速度或位移、机器学习中的特征表示都可使用同一向量运算规则：

```text
[1, 2] + [3, 4] = [4, 6]
2 × [1, 2] = [2, 4]
```

Transformer 的中间表示可按 `[B, T, D]` 排列：`B` 是 batch 大小，`T` 是每个样本的 token 数，`D` 是每个 token 的特征向量长度。例如 `X.shape = [2, 512, 4096]` 表示 2 个样本、每个样本 512 个 token，`X[b, t, :]` 是该 token 的 4096 维特征向量。这里的“4096 维”指向量有 4096 个数值位置，而整个 `X` 的秩是 3。

人工构造的向量如 `[位置, 速度]`，每个位置的含义事先由人指定；模型内部的 4096 个位置没有这样的规定。训练会调整模型参数，使整组数值有助于完成预测；例如后续层可以同时使用多个位置的数值来提取方向信息，而不需要一个固定的“方向位”。因此，向量长度为 4096 不意味着存在 4096 个与位置一一对应、可逐一命名的概念。

高维张量继续增加索引。一批 RGB 图像可表示为 `[批量大小, 高, 宽, 通道]`；`[8, 224, 224, 3]` 表示 8 张 `224 × 224` 图像。实际 Runtime 也常使用 `[批量大小, 通道, 高, 宽]`，并以连续内存、shape 和 stride 表示张量。因此形状只说明排列，不说明维度语义；维度顺序、数据类型、归一化或单位不匹配时，即使形状正确，推理仍可能错误。

多维张量的**维度置换**（permutation）按指定顺序重排所有维度。若 `T` 的形状为 `[d₀, d₁, ..., dₙ]`，置换顺序为 `[p₀, p₁, ..., pₙ]`，则输出 `U` 的第 `j` 维来自 `T` 的第 `pⱼ` 维，形状为 `[d_p₀, d_p₁, ..., d_pₙ]`。元素的数值不变，只是索引位置按同一顺序重排：

```text
U[i_p₀, i_p₁, ..., i_pₙ] = T[i₀, i₁, ..., iₙ]
```

例如，图像张量 `T` 的形状为 `[N, C, H, W]`，使用置换顺序 `[0, 2, 3, 1]` 后，`U` 的形状为 `[N, H, W, C]`；原始元素 `T[n, c, h, w]` 位于 `U[n, h, w, c]`。在 PyTorch 中写作 `T.permute(0, 2, 3, 1)`。

`transpose(dim0, dim1)` 是置换的一个特例：它只交换指定的任意两维，其余维度保持原顺序。例如 `T.transpose(1, 2)` 会将 `[N, C, H, W]` 变为 `[N, H, C, W]`，并使 `T[n, c, h, w]` 位于结果的 `[n, h, c, w]`。维度位置改变时，必须同步确认每个维度的语义仍符合后续算子的输入约定。

## 矩阵计算

神经网络中常见的两类乘法不能互换。

### 点积

两个等长向量的**点积**（dot product）是对应元素相乘后求和，结果是一个数。例如 `[1, 2] · [5, 7] = 1 × 5 + 2 × 7 = 19`。

在 PyTorch 中，两个一维张量的点积写作 `a @ b`，也可用 `torch.dot(a, b)`。

### 逐元素运算

**哈达玛积**（Hadamard product）要求两个张量形状相同，并按位置相乘：

```text
A = [[1, 2],      B = [[5, 6],      A ⊙ B = [[ 5, 12],
     [3, 4]]           [7, 8]]               [21, 32]]
```

即 `(A ⊙ B)[i, j] = A[i, j] × B[i, j]`。它常用于逐元素门控、掩码和缩放。

在 PyTorch 中，逐元素乘法写作 `A * B`，也可用 `torch.mul(A, B)`；输入形状相同时对应这里的哈达玛积，`*` 也支持广播。

### 矩阵乘法

矩阵乘法以左矩阵的一行和右矩阵的一列做点积。设 `A`、`B` 都是实数矩阵：

```text
C = AB
A ∈ ℝ^(M × K),  B ∈ ℝ^(K × N)
C ∈ ℝ^(M × N)

C[i, j] = Σ(k=1..K) A[i, k] × B[k, j]    (1 ≤ i ≤ M, 1 ≤ j ≤ N)

A = [[1, 2],      B = [[5, 6],
     [3, 4]]           [7, 8]]

AB = [[1 × 5 + 2 × 7, 1 × 6 + 2 × 8],
      [3 × 5 + 4 × 7, 3 × 6 + 4 × 8]]
   = [[19, 22],
      [43, 50]]
```

`ℝ` 表示实数集；`M` 是 `A` 的行数，`N` 是 `B` 的列数，`K` 是 `A` 的列数（也必须等于 `B` 的行数）。因此输出 `C` 的形状为 `M × N`，而每个元素都沿 `K` 个对应元素相乘并求和。

在 PyTorch 中，矩阵乘法写作 `A @ B`，也可用 `torch.matmul(A, B)`。`@` 用于两个一维张量时则计算点积。

矩阵乘法满足**结合律**：`(AB)C = A(BC)`，即连续相乘时可以先计算左边或右边的一对矩阵；也满足**分配律**：`A(B + C) = AB + AC`，即矩阵可以对加法逐项相乘。但它通常不满足交换律：同一组矩阵反过来相乘时，结果为 `BA = [[23, 34], [31, 46]]`，因此 `AB ≠ BA`。

非方阵也遵循相同规则。例如 `A` 为 `2 × 3`、`B` 为 `3 × 2` 时，内侧维度均为 `3`，因此可以相乘并得到 `2 × 2` 的结果：

```text
A = [[ 1, 0, 2],     B = [[3, 1],     AB = [[3, 11],
     [-1, 3, 1]]          [2, 4],           [3, 16]]
                           [0, 5]]
```

### 线性层

矩阵与列向量相乘是神经网络线性层的一个单样本形式：

```text
W = [[1, 2],      x = [[5],      Wx = [[1 × 5 + 2 × 6],
     [3, 4]]           [6]]            [3 × 5 + 4 × 6]]
                                    = [[17],
                                       [39]]
```

若将单个样本的特征写成列向量，线性层采用数学教材中常见的形式：`y = Wx + b`。PyTorch `nn.Linear` 则将一批样本按行堆叠，计算形式为：

```text
Y = XWᵀ + b
```

两种形式表达的是相同的线性变换，差别在于样本和权重在矩阵中的排列方式。设 `N` 是 batch 大小、`in_dim` 是输入特征数、`out_dim` 是输出特征数，各符号的含义如下：

| 符号 | 含义与形状 |
|---|---|
| `x` | 单个输入列向量，形状为 `[in_dim, 1]`。 |
| `y` | 单个输出列向量，形状为 `[out_dim, 1]`。 |
| `X` | 批量输入；每行一个样本，形状为 `[N, in_dim]`。 |
| `W` | 权重矩阵；在 PyTorch `nn.Linear.weight` 中形状为 `[out_dim, in_dim]`。 |
| `Wᵀ` | `W` 的转置（行、列互换），形状为 `[in_dim, out_dim]`，使其可与 `X` 相乘。 |
| `b` | 偏置，形状为 `[out_dim]`；计算时广播到 batch 中每一行。 |
| `Y` | 批量输出，形状为 `[N, out_dim]`。 |

因此，`XWᵀ` 的形状为 `[N, out_dim]`，再加上 `b` 后得到 `Y`。

### GEMM

GEMM（General Matrix Multiply）是计算库和 GPU 中常用的矩阵乘法接口，通常表示 `C = αAB + βC`。线性层、注意力投影和 MLP 都包含大量 GEMM，所以它常占据推理性能的主要部分。

## 浮点数的表示与转换

计算机通常用符号位、指数域和小数域编码浮点数。对有限的规格化数，设符号位为 `s`、存储的指数为 `E`、小数域为 `F`，其数值为 `(-1)^s × (1.F)₂ × 2^(E-偏移量)`。其中，有效数字开头的 `1` 不占存储位。零、非规格化数、无穷大和 NaN 使用其他编码规则。

深度学习中常见的浮点格式如下：

设指数域有 `k` 位、小数域有 `m` 位、指数偏移量为 `b`。这些格式使用 `b = 2^(k-1) - 1`。规格化数的存储指数 `E` 从 `1` 到 `2^k - 2`，实际指数为 `e = E - b`，因此 `e` 的范围是 `1 - b` 到 `2^k - 2 - b`。小数域有 `m` 位，规格化数隐含开头的 `1`，所以有效数字有 `m + 1` 个二进制有效位；位数越多，精度越高，约相当于 `(m + 1) × log10(2)` 位十进制有效数字。小数域也影响数值边界：最小正规格化正数为 `2^(1-b)`，最大有限值为 `(2 - 2^(-m)) × 2^(2^k - 2 - b)`；`E = 0` 编码非规格化数时，最小正值为 `2^(1-b-m)`。

| 格式 | 位数（符号／指数／小数） | 偏移量 `b` | 规格化指数范围 `e` | 正规格化数范围（最小～最大） | 最小正非规格化数 | 有效精度（约） |
| --- | --- | --- | --- | --- | --- | --- |
| FP32（binary32） | 1／8／23 | 127 | `-126`～`+127` | `1.175 × 10^-38`～`3.403 × 10^38` | `1.401 × 10^-45` | 24 位二进制（约 7 位十进制） |
| FP16（binary16） | 1／5／10 | 15 | `-14`～`+15` | `6.104 × 10^-5`～`65504` | `5.960 × 10^-8` | 11 位二进制（约 3 位十进制） |
| BF16（非 IEEE 754 标准格式） | 1／8／7 | 127 | `-126`～`+127` | `1.175 × 10^-38`～`3.390 × 10^38` | `9.184 × 10^-41` | 8 位二进制（约 2 位十进制） |

表中的数值范围为格式理论值；负数范围与正数对称，此外还包括零和非规格化数。数值是离散的，并非区间中的每个实数都可表示。实际硬件指令对非规格化数的处理可能不同。

下面以可被 FP16 精确表示的 `5.25` 为例，逐步推导数值如何编码为字节，以及如何从字节还原。

### 从十进制文本到存储字节

1. 解析十进制文本 `5.25`，得到数值 `5.25₁₀ = 5 + 0.25`。整数部分 `5 = 4 + 1 = 101₂`；小数部分 `0.25 = 1/4 = 2⁻² = 0.01₂`，所以 `5.25₁₀ = 101.01₂`。
2. 将二进制小数点左移两位，使其成为 `1.x` 的形式：`101.01₂ = 1.0101₂ × 2²`。因此实际指数 `e = 2`，有效数字为 `1.0101₂`。
3. 数值为正，符号位 `s = 0`。FP16 指数偏移量为 15，所以存储的指数 `E = e + 15 = 2 + 15 = 17 = 16 + 1 = 10001₂`，占 5 位。
4. 规格化数有效数字开头的 `1` 是隐含位，无须存储。去掉它后，小数部分为 `0101`；在右侧补 6 个 `0`，填满 FP16 的 10 位小数域，得到 `F = 0101000000`。
5. 按 1 位符号、5 位指数、10 位小数拼成 16 位：`0 | 10001 | 0101000000 = 0100010101000000₂`。从左到右每 4 位分组，得到 `0100 0101 0100 0000₂ = 0x4540`。
6. 这个 16 位模式的高字节是 `45`，低字节是 `40`。存入小端内存时，低字节放在低地址，因此按地址从低到高读到的两个字节为 `40 45`。

### 从存储字节到十进制文本

1. 按小端字节序从低地址读到 `40 45`。其中 `40` 是低字节，`45` 是高字节；按高字节在前重组，得到位模式 `0x4540 = 0100010101000000₂`。
2. 按 FP16 的 1、5、10 位字段拆分：`0 | 10001 | 0101000000`。符号位 `s = 0`，表示正数。
3. 指数域 `10001₂ = 16 + 1 = 17`。它既不是全 0，也不是全 1，因此这是规格化数；减去 FP16 的偏移量 15，得到实际指数 `e = 17 - 15 = 2`。
4. 小数域 `0101000000₂` 的第 2、4 个小数位是 `1`，其余为 `0`，对应的值为 `2⁻² + 2⁻⁴ = 1/4 + 1/16 = 0.3125`。补回规格化数隐含的整数位 `1`，有效数字为 `1.0101₂ = 1 + 0.3125 = 1.3125`。
5. 用符号、有效数字和实际指数还原数值：`(-1)^0 × 1.3125 × 2² = 1.3125 × 4 = 5.25`。本例没有精度损失；将该数值格式化为十进制文本，得到 `5.25`。

字节序只影响内存中的字节排列，不改变浮点数的位模式。

### FP16 规格化正数的最小值与最大值

**最小正规格化正数：指数最小，小数全 0**

```text
符号位 | 指数域 | 小数域
   0   | 00001  | 0000000000

数值 = 1.0₂ × 2^(1−15) = 2⁻¹⁴ ≈ 0.00006104
```

**最大正规格化正数：指数最大，小数全 1**

```text
符号位 | 指数域 | 小数域
   0   | 11110  | 1111111111

数值 = 1.1111111111₂ × 2^(30−15) = 65504
```

FP16 规格化数的指数编码可用范围是 `00001`～`11110`；`00000` 留给零和非规格化数，`11111` 留给无穷大和 NaN。

### FP16 累加中的精度损失

以 `4096` 连续加 `1` 为例，假设每一步都按最接近的可表示值舍入，并将结果存回 FP16。两个输入都能被 FP16 精确表示，但加法结果未必能精确表示。

加法先对齐指数，再计算精确结果：

```text
4096 = 1.000000000000₂ × 2¹²
   1 = 0.000000000001₂ × 2¹²

  1.000000000000₂ × 2¹²
+ 0.000000000001₂ × 2¹²
────────────────────────
  1.000000000001₂ × 2¹² = 4097
```

FP16 小数域只有 10 位，增量 `1` 对应的非零位位于小数点后第 12 位，超出了可保留的位置：

```text
隐含整数位 | 保留的 10 位小数 | 超出的位
     1     | 0000000000      | 01
```

在 `4096 = 2¹²` 及其上方的同一指数区间，相邻 FP16 数的间隔为 `2¹² × 2⁻¹⁰ = 4`。精确结果 `4097` 介于 `4096` 和 `4100` 之间，距前者为 `1`、距后者为 `3`，所以舍入为 `4096`，这次加进去的 `1` 就丢失了。

```text
4096 + 1 → 4096
4096 + 1 → 4096
……重复 10 次

数学结果：4106
每一步存回 FP16 的累加结果：4096
```

每次累加都从已经舍入的 `4096` 开始，所以小增量一直无法积累。浮点格式的有效位数固定，数值越大，相邻可表示值的间隔通常也越大。若使用 FP32 累加器，这 10 次加法可以得到精确的 `4106`；最终转回 FP16 时仍需舍入，但能避免每一步都丢失增量。

## BF16 与计算精度

BF16 使用 1 位符号、8 位指数和 7 位小数域，指数偏移量为 127。`5.25` 在 BF16 中的位模式是 `0 | 10000001 | 0101000 = 0x40A8`，仍可精确表示；其他数值可能因小数域较短而需要舍入。

GEMM 的输入、权重和输出可以采用不同浮点精度。FP32 具有较多有效数字；BF16 有较少有效数字但数值范围接近 FP32，通常能减少显存占用和内存传输，并能利用支持 BF16 的 GPU 专用矩阵运算单元。

实际推理常采用 `BF16 × BF16 → FP32 累加`，在吞吐量和数值误差间折中。BF16 结果通常不会与 FP32 逐位一致；是否满足特定模型的输出契约，必须由相应的正确性回归验证。
