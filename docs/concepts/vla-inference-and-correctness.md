# VLA 推理路径、动作生成与正确性

本文介绍从模型制品到动作输出的 VLA 推理路径、主要动作生成方法及正确性的分层理解。它只说明通用概念；当前选定模型、Runtime、配置和实验结论以[项目范围](../project/scope.md)、[执行计划](../plans/phase-0.md)和[实验记录](../../experiments/README.md)为准。

## 模型推理与部署路径

训练完成后，需要一条可执行的路径将外部输入转换为动作：

```text
输入资产
   ↓
预处理与序列化
   ↓
Runtime 加载模型并执行计算
   ↓
后处理与反序列化
   ↓
动作张量或动作序列
```

任何一层变化都可能影响正确性、性能或资源消耗。模型本身与运行模型的软件不是同一概念：

| 概念 | 含义 |
|---|---|
| 模型结构 | 网络由哪些层、算子和数据流组成 |
| Checkpoint | 训练中保存的参数及相关状态；推理通常只需前向计算所需部分 |
| 模型制品 | Runtime 实际加载的文件，可能由 checkpoint 转换、合并或量化得到 |
| Runtime | 加载模型、组织算子并调度 CPU、GPU 等设备执行推理的软件 |
| Backend | Runtime 面向某类硬件或计算库的执行实现，例如 CPU 或 CUDA backend |
| Revision | 代码、模型或配置在版本历史中的确定版本 |
| SHA-256 | 核对文件字节身份的摘要；相同摘要不代表语义或性能正确 |

### 模型格式、GGUF 与量化

模型格式规定参数、张量元数据等如何存储。GGUF 是模型容器，不等同于量化算法，也不天然代表某一数值精度；同一格式可保存不同类型和精度的张量。

量化以更少位数或更紧凑表示保存、计算参数或 activation，通常可减少模型大小、内存流量和显存占用，并可能提高速度，但实际收益取决于硬件、backend、算子实现和工作负载。转换也可能改变张量布局、合并辅助模块或补充运行时元数据。因此，可复现实验除模型名称外还应确定上游 checkpoint、转换后制品、转换方法和文件身份。

### 输入输出契约

VLA 的输入不只是抽象的“图像和文字”。实际路径还需明确：

- 图像尺寸、颜色通道、归一化方式和排列顺序；
- 文本的 tokenization、特殊 token 和序列长度；
- 机器人状态的维度、顺序、单位、归一化和缺失值处理；
- action tensor 的形状、有效维度、填充值和反归一化规则。

这些共同构成输入输出契约。即使形状正确，预处理、维度语义或反归一化不匹配仍会产生数值有限却语义错误的动作。

### 模型加载、冷启动与稳态请求

模型加载包含读取制品、分配内存、初始化 backend，并可能创建或编译执行资源；首次推理也可能触发额外初始化。因此应区分：

```text
进程启动 + 模型加载 + 首次初始化 + 单次推理
```

与：

```text
模型已加载 + 同一进程内的重复推理
```

前者描述冷启动或一次性任务体验，后者描述常驻服务的稳态请求；不能把重复启动 CLI 的总时间当作同进程稳态推理延迟。

### CPU、GPU 与 CUDA 软件栈

典型 CUDA 路径中，CPU 负责程序控制、输入处理和提交 GPU 工作，GPU 以大量并行线程执行 kernel。主机内存与显存之间的传输、提交、执行和同步共同构成端到端路径。

NVIDIA driver、CUDA Toolkit、CUDA Runtime/API 与 GPU Compute Capability 分别代表驱动支持、开发组件、应用调用的运行接口和硬件能力等级。驱动显示的最高 CUDA 版本、本机 Toolkit 版本与应用实际使用的运行库版本不是同一值。CUDA Graphs 可记录并重放重复 GPU 工作以减少 CPU 提交开销，但是否改善端到端指标仍须用 profile 和前后测量确认。

## VLA 如何学习与生成动作

VLA（Vision-Language-Action）典型地接收摄像头图像、语言指令和机器人当前状态，并输出未来一段动作。许多 VLA 的核心策略训练属于模仿学习或行为克隆，训练样本由图像、指令、机器人状态与专家实际执行的动作组成；专家轨迹可来自人工遥操作、传统控制器、仿真或已有策略。

```text
图像 + 指令 + 机器人状态
              ↓
       视觉语言主干
              ↓
         条件特征
              ↓
           动作头
              ↓
         动作序列
```

视觉语言主干理解场景和任务，动作头将条件特征转为动作。完整训练还可能使用视觉语言预训练、多机器人联合训练、强化学习、偏好优化、蒸馏或量化感知训练；这些与动作头的建模方式是不同维度。

输出必须与目标机器人的 embodiment 对齐。Embodiment 包括关节数量、坐标系、传感器、夹爪、控制频率和动作定义。动作通常按训练数据统计量归一化，推理时需用匹配的统计量反归一化；维度顺序、单位或统计量不一致可使结构合法的数值成为错误控制量。

### 动作头与 action chunking

| 类型 | 训练方式 | 推理方式 | 主要特点 |
|---|---|---|---|
| 直接回归 | 预测动作接近专家动作 | 一次输出连续动作 | 简单、快速，但可能平均多种合理动作 |
| 自回归动作 token | 预测离散动作 token | 逐 token 生成 | 可复用语言模型结构，但需离散化 |
| 扩散 | 学习从带噪动作恢复专家动作 | 从 noise 多步去噪 | 可表达多种动作，但计算步骤多 |
| Flow matching | 学习从 noise 到专家动作的速度场 | 沿速度场多步积分 | 支持连续多模态动作分布 |
| CVAE / 混合密度模型 | 学习随机隐变量或多个分布 | 采样后生成 | 可表达多种动作模式 |

Action chunking 表示一次推理预测未来 `N` 步动作，不等同于动作头类型。控制端可仅执行前 `K` 步后重新观察和规划：执行步数少可提高闭环反馈频率，但推理延迟预算更紧；执行步数多可摊薄推理开销，却会增加后续动作基于旧观察的开环误差。重规划频率由实际执行步数、控制频率和推理调度共同决定。

### 扩散、Flow Matching 与 initial noise

扩散在训练中逐渐为真实动作加噪并学习反向去噪；推理由随机 noise 经多步去噪得到动作。Flow matching 则学习连续速度场：

```text
dx/dt = vθ(x, t, condition)
```

其中 `x` 是当前动作候选，`t` 是生成过程时间，`condition` 是图像、指令和状态，`vθ` 是模型预测的移动方向。推理时从随机 noise 出发，沿速度场积分到最终动作。二者都是从简单随机分布到复杂动作分布的变换，但训练目标和生成方程不同；将 flow matching 通俗称为“去噪”并不严格。

对生成式动作头，initial noise 是模型真正接收的随机起点，而不是图像或硬件噪声。不同 noise 可在相同图像、指令和状态下生成不同合理动作。Seed 仅用于初始化伪随机数生成器；只有算法、状态和采样顺序等条件一致时，才足以复现同一 noise。Temperature 与 token sampling 也不等同于 noise。

实验中可直接固定 noise，使基线和优化版接收字节相同的随机输入，排除随机采样这一混杂因素；但模型制品、软件版本、硬件、其他输入和执行条件仍须受控，且并行计算可能存在数值非确定性。固定 noise 是实验控制手段，不表示部署时必须恒定。直接回归或确定性 token 解码的 VLA 也可能不使用 initial noise。

## 如何理解 VLA 输出的“正确”

接口结构合法、数值可重复或优化前后回归一致、动作语义正确和闭环任务成功回答不同问题；前一层成立不代表后一层成立。

### 接口与结构合法

原始输出应满足冻结的接口契约：无 `NaN`/`Inf`，形状与数据类型正确，有效维度和填充值符合约定，归一化与反归一化匹配 checkpoint、数据集和机器人。映射到具体控制接口后，才可进一步检查关节位置、速度、加速度、单步位移和夹爪取值是否越界。

### 数值可重复与优化前后回归

数值可重复表示在声明的相同条件下重复运行，差异处于预先确定的范围。优化前后回归表示两个实现都在冻结输入和判定标准下通过检查；它仅支持已测范围内的一致性，不证明所有输入上等价。浮点运算顺序、并行归约、数学库和硬件实现可造成微小差异，因此不必要求逐 bit 相同。

连续动作可按有效维度、绝对误差、相对误差或任务相关容差比较。容差必须在观察待评估结果前，依据输出尺度、参考实现或基线重复性确定，不能事后选择。

### 动作语义与闭环任务正确

动作语义正确要求有效维度的含义、顺序、坐标系、方向、单位、尺度和控制模式与机器人接口一致。同一数值可能是关节绝对位置、关节增量、末端速度或归一化控制量；应通过 checkpoint/数据集元数据、预后处理实现、接口定义和已知样本核对。它不证明策略能完成任务。

闭环任务正确则要求策略在持续观察、执行和重规划中达到任务目标，依赖匹配的 embodiment、正确的输入输出处理、合适的生成目标、闭环调度以及仿真或真实机器人的成功率验证：

```text
观察 → 预测一段动作 → 执行前几步 → 重新观察并再次预测
```

完整验证的层级是：

```text
输出结构正确
→ 数值有限且范围合法
→ 固定输入和 noise 下结果可重复
→ 优化前后通过已测范围内的正确性回归
→ 动作尺度和语义正确
→ 闭环任务具有足够成功率
```
