# RoboEdge：项目定位

> 状态：Problem Discovery。本文区分项目动机、调查约束和候选场景；不包含已确认的用户问题或最终解决方案。

## 1. 项目动机

项目发起人希望通过真实 Issue 的复现、根因分析、最小修复和影响验证，证明能够解决 VLA 推理与机器人部署中的实际工程问题。

这些结果可以形成适用于以下岗位的可验证工程证据：

- C++ AI 推理/模型部署工程师；
- TensorRT/CUDA 推理优化工程师；
- 端侧/边缘 AI 系统工程师；
- 机器人模型部署与系统集成工程师；
- AI 推理基础设施和 GPU 系统性能工程师。

期望展示的能力包括问题复现、根因分析、Python/C++ 工程、模型部署、Processor、CUDA/TensorRT、协议与控制端、正确性分析、GPU Profiling、系统可靠性、机器人集成和可重复交付。

岗位方向和已有 C++ 能力是个人背景，不是用户问题或问题筛选门槛。技术名词数量、架构复杂度或完整闭环本身也不是能力证据；能力只能由可重复问题、根因、最小修复、取舍记录和影响验证证明。

## 2. 当前项目定位

当前项目不是一个已经确定要建设的 VLA Runtime，而是一项 VLA 部署生态的 Problem Discovery：

> 识别并验证 VLA 推理与机器人部署中一个真实存在、可重复、尚未被现有方案充分解决且值得投入的问题。

模型官方参考、上游实现和 Issue 所在工作流是默认调查对象。`vla.cpp`、`Embodied.cpp` 和 GR00T 官方部署路径只在问题相关时作为对照、诊断、修复或上游贡献工具，不是必经路径。

问题成立前，项目不声称：

- 市场缺少 C++ VLA Runtime；
- 现有方案缺少完整 Processor、动作生命周期、安全进程或 ROS2；
- 现有方案不能完成仿真或机器人闭环；
- 现有性能、故障恢复或制品能力不满足实际需求；
- 新建一条 C++ 安全控制链路是必要方案。

以上内容都是需要代码检查或实验验证的 Hypothesis。

## 3. 候选用户与工作流

首个候选用户是：需要把开源 VLA 接入本地仿真或机器人控制链路的部署工程师。

候选工作流包括：

1. 固定 Issue、受影响版本、环境和用户工作流；
2. 使用问题原生实现完成最小复现；
3. 建立预期行为、官方参考或已有测试基线；
4. 定位模型、Processor、Runtime、协议或控制端根因；
5. 在适当层级和语言中完成最小修复；
6. 增加回归测试并检查最新版本、替代方案和相关 PR；
7. 执行与问题声明匹配的影响验证，例如回归、数值/资源测量、LIBERO、最小仿真或控制端测试。

候选用户和工作流尚未经过访谈或本地复现确认。Problem Discovery 可以缩小、替换或否定它们。

## 4. 候选调查场景

“受限固定工位中的语言条件物料拣选与定点放置”保留为候选调查场景，因为它可以提供图像、语言、机器人状态和动作闭环，但目前不代表已有客户、产线、真机需求或 VLA 业务必要性。

如果固定视觉、规则状态机和传统规划已经能够以更低成本完成任务，这不妨碍把该场景用作问题调查或影响验证负载，但项目不能据此宣称 VLA 具有工业业务价值。

是否使用该场景取决于：

- 本地资源是否能够稳定复现；
- 被选 Issue 的原生路径和预期行为是否能够固定；
- 能否生成跨方案一致的固定输入；
- 能否观察到对部署工作流有明确影响的问题。

## 5. 调查约束

当前约束：

- 优先调查 VLA 推理或机器人部署中真实、可复现且具有工程深度的问题；
- C++、Python、CUDA/TensorRT、Processor、协议或控制端只根据根因和最小修复需要选择；
- 只进行最小、非生产化的复现和故障实验；
- 不训练新的核心 VLA；
- 不预先建设通用框架、多模型切换、云端控制或功能安全系统；
- 不把公开 benchmark、官方声明或候选设计当成本地证据；
- 没有有价值的缺口时，允许停止、转向或改为上游贡献。

这些约束可以控制调查范围，但不能预先规定问题答案或最终实现技术栈。

## 6. 能力声明边界

| 已有证据 | 可以声明 | 不能声明 |
|---|---|---|
| 官方资料核查 | 完成指定版本的生态调查 | 已复现或证明某项能力缺失 |
| 本地 smoke test | 在固定环境复现指定路径 | 发现了值得独立立项的问题 |
| 稳定问题复现 | 观察到指定问题及直接影响 | 其他方案均不能解决 |
| 替代方案反证 | 问题未被已调查方案解决 | 已经选定最终架构 |
| 问题陈述与验收证据 | 可以决定继续、上游贡献或转向 | 可以外推为通用行业问题 |

详细证据要求和退出条件见 [Problem Discovery 计划](../plans/phase-0.md)。
