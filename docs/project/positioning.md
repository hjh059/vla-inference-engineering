# VLA 推理部署与优化：项目定位

> 本文只维护项目动机、交付边界和能力声明规则；当前阶段以[仓库入口](../../README.md)和[执行计划](../plans/phase-0.md)为准。

## 1. 项目动机

项目通过完整的 VLA 部署、正确性基线、性能测量、GPU profiling、最小优化和影响验证，形成面向以下岗位的可验证工程证据：

- C++ AI 推理/模型部署工程师；
- TensorRT/CUDA 推理优化工程师；
- 端侧/边缘 AI 系统工程师；
- 机器人模型部署与系统集成工程师；
- AI 推理基础设施和 GPU 系统性能工程师。

项目展示的能力包括：现有路径部署、可复现实验、Python/C++ 工程、正确性分析、性能测量、GPU profiling、瓶颈定位、优化取舍和结果交付。技术名词数量、架构复杂度或完整机器人闭环本身不构成能力证据。

## 2. 当前项目定位

本项目把一条现有 VLA 路径的可复现实验证据链作为主交付，而不是预先建设通用 VLA Runtime。规范性的实施范围、非目标、冻结条件和交付要求只在[部署与性能优化范围](scope.md)维护；当前进度、正式配置和测量结论分别由执行计划、实验配置和实验结果维护。

模型官方参考、上游实现、公开 Issue 和 benchmark 都可以作为辅助证据，用于选择场景、确认约束或解释结果。它们不替代本地基线和测量。

## 3. 对外叙述边界

本文不重复枚举实施排除项或冻结字段。对外介绍本项目时，应保持以下边界：

- 项目展示的是在固定配置中部署、测量、profiling 与验证优化的能力，不宣称通用 Runtime、完整机器人闭环或生产控制系统；
- 正确性、性能和优化收益只能表述为有相应本地证据支持的范围，不能由官方资料、公开 benchmark 或单次运行替代；
- 需要更换模型、设备、输入或其他冻结条件时，适用范围随新的 `Configuration ID` 变化，不能与原结果混合比较。

## 4. 能力声明边界

| 已有证据 | 可以声明 | 不能声明 |
|---|---|---|
| 官方资料核查 | 固定版本下的路径、能力或限制候选 | 已在本地成功部署或性能达标 |
| 本地 smoke test | 指定路径可在声明环境中启动或运行 | 形成可比较的性能结论 |
| 固定配置的正确性/性能基线 | 该配置下的行为与定量结果 | 其他模型、设备或输入也相同 |
| Profile 工件 | 已测量到的热点或等待关系 | 未验证层级一定是根因 |
| 优化前后验证 | 该优化在固定配置下的改进和取舍 | 通用最优方案或生产可用性 |
