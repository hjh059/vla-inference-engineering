# RoboEdge：项目定位

> 状态：可行性验证。本文维护项目动机、交付边界和能力声明规则；正式性能实验开始前将冻结一组模型、设备和任务配置。

## 1. 项目动机

项目通过完整的 VLA 部署、正确性基线、性能测量、GPU profiling、最小优化和影响验证，形成面向以下岗位的可验证工程证据：

- C++ AI 推理/模型部署工程师；
- TensorRT/CUDA 推理优化工程师；
- 端侧/边缘 AI 系统工程师；
- 机器人模型部署与系统集成工程师；
- AI 推理基础设施和 GPU 系统性能工程师。

项目展示的能力包括：现有路径部署、可复现实验、Python/C++ 工程、正确性分析、性能测量、GPU profiling、瓶颈定位、优化取舍和结果交付。技术名词数量、架构复杂度或完整机器人闭环本身不构成能力证据。

## 2. 当前项目定位

主交付由[部署与性能优化范围](scope.md#项目目标)定义：先以有限可行性验证选择一条现有部署路径，再在固定实验配置上完成端到端部署、基线、profiling 和优化验证。项目不预先建设通用 VLA Runtime。

模型官方参考、上游实现、公开 Issue 和 benchmark 都可以作为辅助证据，用于选择场景、确认约束或解释结果。它们不替代本地基线和测量。

可行性阶段不预设最终模型或优化手段；配置一旦进入正式基线，其冻结条件与实现版本的对比规则按[正式基线配置](scope.md#正式基线配置)执行。需要更换冻结条件时，应建立新的实验配置，不能与原基线混合比较。

## 3. 项目边界

当前约束：

- 优先选择可在资源和时间边界内跑通的现有 VLA 部署路径；
- 正式优化只针对 profile 证据支持的一个主要瓶颈；
- 正确性、性能和资源指标由选定任务场景推导，并在查看优化结果前固定；
- C++、Python、CUDA/TensorRT、Processor、协议或控制端只按路径和瓶颈需要选择；
- 不训练新的核心 VLA，不预先建设通用框架、多模型切换、云端控制或功能安全系统；
- 不将公开 benchmark、官方声明或单次运行包装成本地性能结论；
- 不因性能提升而外推为所有模型、硬件或机器人工作流均适用。

## 4. 能力声明边界

| 已有证据 | 可以声明 | 不能声明 |
|---|---|---|
| 官方资料核查 | 固定版本下的路径、能力或限制候选 | 已在本地成功部署或性能达标 |
| 本地 smoke test | 指定路径可在声明环境中启动或运行 | 形成可比较的性能结论 |
| 固定配置的正确性/性能基线 | 该配置下的行为与定量结果 | 其他模型、设备或输入也相同 |
| Profile 工件 | 已测量到的热点或等待关系 | 未验证层级一定是根因 |
| 优化前后验证 | 该优化在固定配置下的改进和取舍 | 通用最优方案或生产可用性 |

详细执行步骤、证据和完成标准见[部署基线与优化计划](../plans/phase-0.md)。
