# 实验记录与工件管理

本目录保存项目自己产生的可复现实验证据。内容按职责和复现价值归属，不按当前工作区的物理目录整体搬运。

## 仓库职责

- 本仓库管理计划、文档、`Configuration ID`、实验脚本、原始日志、CSV/JSON 指标、环境记录、profile 工件和校验和；
- `vla.cpp` 源码由个人 fork `git@github.com:hjh059/vla.cpp.git` 管理；正式基线固定到 `e9e57ea734692bbcb34528fee16318e230ba1100`，优化以该 fork 上的新 commit 表示；
- 模型本体不提交。本仓库只记录来源、固定 revision、许可证、大小和 SHA-256；
- `build-cuda/` 等生成物不提交。本仓库只记录构建命令、CMake 选项、工具链版本和可执行文件 SHA-256；
- 本项目产生的 `.ncu-rep`、`.nsys-rep`、导出 SQLite 及其小型原始结果直接保存在对应实验目录；每项保留可定位的索引、大小和 SHA-256；
- 不得只引用项目外临时路径作为长期证据。模型本体与构建产物仍不受本仓库版本管理，必须在对应正式配置中记录来源、版本、构建配置和 SHA-256。

## 目录规则

- 正式基线及其优化对比：`experiments/<Configuration ID>/`。

冻结配置后，与正式比较有关的配置、命令、原始结果和工件索引必须集中在对应的 `experiments/<Configuration ID>/` 中。选路阶段的结论只在项目文档中简要记录，不单独保留实验工件目录。

## 原始证据规则

- 纳入当前有效证据集的原始日志保持原样，修正和解释写在同目录索引中，不反向修改日志观察值；确认废弃且不再承担证据职责的工件直接删除，不继续保留在活跃文档或工件清单中；
- 派生结果必须记录计算范围和方法，并能从已保存的原始证据重新生成；
- 未归档的大型工件、未记录的命令和未冻结的随机输入必须明确标记为缺口；
- 校验和只证明字节身份，不证明模型语义、性能或优化效果。
- 仓库内实验工件的字节身份只写入对应实验目录的机器可读 `.sha256` 清单；结果和工件说明文档只链接该清单，不复制其中的 hash；所有清单路径均以工作区根目录 `/root/vla-smoke-c01` 为执行基准；
- 不纳入仓库的冻结模型、输入和补丁身份只在 `CONFIGURATION.md` 维护，基线构建快照只在对应环境记录中维护；若同一身份已进入 `.sha256` 清单，其他文档不得再次抄写；
- 不同路径保存字节完全相同的工件时，清单中允许出现相同 digest；每一行仍校验一个独立路径，这不构成第二个权威来源。
