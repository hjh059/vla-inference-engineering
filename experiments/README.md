## 实验比较规则

- 正式测量前固定模型/checkpoint、设备、驱动与关键依赖、构建选项、输入、noise 或随机种子、线程数、正确性标准和测量方法；测量方法包括计时边界、预热次数、样本数、统计与异常样本处理。
- 冻结条件与实验标识统一记录在 [01-baseline/README.md](01-baseline/README.md#冻结配置)。各次优化分别记录实现 revision、改动、复现命令、正确性回归及性能结果。
- 优化前后比较只改变明确记录的目标实现，其他冻结条件保持一致。变更冻结条件时使用新的实验标识并重新建立基线，不将不同条件的结果作为同一优化的前后比较。
- 性能比较使用独立于 profiler 的正式测量；profile 采集结果用于热点与机制分析。正确性标准和测量方法在查看优化结果前确定。

## 工件保存规则

- 各阶段目录保存其原始样本、参考输出、日志、环境记录、profile 报告及必要脚本；模型本体与构建产物不提交，保留其来源、版本、构建条件和字节身份。
- 有效原始数据和日志保持原样，修正与解释写入对应分析或工件说明；历史路径保留原样，当前归档位置以阶段文档和校验清单为准。
- 派生结果记录计算范围与方法，并能从已保存的原始证据重新生成。
- 大型 profile 工件需归档并索引，不能仅引用项目外临时路径；未归档工件、未记录命令或未冻结随机输入等证据缺口须明确标注。
- 仓库内归档工件的 SHA-256 统一维护在各阶段的 `.sha256` 清单中，说明文档链接清单，不重复抄写摘要值。清单路径以采集工作区根目录 `/root/vla-smoke-c01` 为基准；相同相对目录结构下可在其他工作区根目录验证。
- 未纳入仓库的模型、输入资产及补丁身份由基线配置维护，构建制品快照由对应环境记录维护。SHA-256 只证明字节身份，不证明正确性或优化效果。
